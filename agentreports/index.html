I use a lot of coding agents, and at the start of October I blew through my whole monthly OpenCode Go allowance in about two weeks. When I had it audited, the models weren’t really the problem, it was how I was using them (18 model calls per message, about 150k tokens on an average call, and one file read 198 times in a single session). agentreports is basically that audit, run for me every Monday morning.

It reads every session my agents ran that week (Claude Code, Codex, OpenCode and Pi) and writes two reports, one on where the tokens went and what was wasted, and one on how I write prompts and what that costs me. Each report is compared with the one before, so I can see whether I’m actually getting any better.

How a report gets made

Code does the counting and models only do the judging. First the code reads and prices every call, removing the copies that resumed sessions make, and runs a set of detectors: cache expiry after idle gaps, context past 100k, big tool output carried for the rest of a session, files re-read unchanged, a top-tier model on light turns, and retry loops. For prompts it looks for vague openers, corrections, bare “continue” turns and marathon sessions. Each finding comes with its evidence and a dollar estimate.

Then Haiku workers run in parallel over the costliest sessions and grade how a sample of them were prompted, and one Sonnet call turns the figures, the signals, the worker notes and last week’s report into findings. After that the code checks the result. Findings have to point at real signals, trends and savings come from the data, and any number in the text that doesn’t match the input gets listed in the report.

Keeping it cheap

It’d be a bit daft for a tool about wasted tokens to waste tokens. A bare claude -p call on my machine was carrying about 21k tokens of skills, plugins and settings, and calling it with none of that brought it under 1k (a trivial call went from $0.0027 to $0.00017). A run over 378 sessions costs about 12 cents.

Every model call is cached by its content, so a retried run never pays twice, and a cost ceiling stops a run before it goes over. Only two things ever call a model, pressing Sync now or the timer when a report is due, and opening the panel just reads files. It also ignores its own runs, so it never reports on itself.

The fiddly bits

  • The Claude Code, OpenCode and Codex readers were checked against real history on my machine, and their call and token counts match independent tallies exactly.
  • A systemd timer writes the report on report day, and if the laptop was off it catches up when it wakes or at the next login. A sync late on Sunday won’t leave a 13-hour report for Monday.
  • A sync runs as its own systemd unit, so you can close the panel or the terminal and get a notification when it’s done.
  • Agents delete their own history after a while, so agentreports keeps its own compressed copy of every session it reads.
  • Prompts are stripped of keys, tokens and secrets before they’re stored or sent, and tool output is never sent, only its size.

It’s written in Go with every dependency vendored so it builds offline, and there are 70 tests, including a two-period run against a fake Anthropic API.
