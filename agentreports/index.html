I use a lot of coding agents. Every Monday morning, agentreports reads every session they ran that week and writes two reports: where the tokens went and what was wasted, and how I write prompts and what that costs me.

Each report is compared with the one before, so I can see whether I’m actually getting better.

Code does the counting, models do the judging

  1. Code reads and prices every call. It removes the copies that resumed sessions make, prices each call, and runs detectors: cache expiry after idle gaps, context past 100k, big tool output carried for the rest of a session, files re-read unchanged, a top-tier model on light turns, retry loops. For prompts it looks for vague openers, corrections, bare “continue” turns and marathon sessions. Each finding comes with its evidence and a dollar estimate.
  2. Haiku workers explain. They run in parallel and look at the costliest sessions, and grade how a sample of them were prompted.
  3. Sonnet writes the report. One call turns the figures, the signals, the worker notes and last week’s report into findings.
  4. Code checks the result. Findings have to point at real signals, and trends and savings come from the data. Any number in the text that doesn’t match the input gets listed in the report.

Cheap on purpose

  • A bare claude -p call here carried about 21k tokens of skills, plugins and settings. Calling it with none of that brought it under 1k, and a trivial call went from $0.0027 to $0.00017.
  • Every model call is cached by its content, so a retried run never pays twice, and a cost ceiling stops a run before it goes over.
  • Only two things ever call a model: pressing Sync now, or the timer when a report is due. Opening the panel just reads files.
  • It ignores its own runs, so it never reports on itself.

Getting the details right

  • Checked against real data. The Claude Code, OpenCode and Codex readers were checked against real history on this machine, and their call and token counts match independent tallies exactly.
  • A timer that catches up. A systemd timer writes the report on report day. If the laptop was off, it catches up when the machine wakes or at the next login. A sync late on Sunday won’t leave a 13-hour report for Monday.
  • Syncing in the background. A sync runs as its own systemd unit, so you can close the panel or the terminal and get a notification when it’s done.
  • Keeping history. Agents delete their own history after a while, so agentreports keeps its own compressed copy of every session it reads.
  • Privacy. Prompts are stripped of keys, tokens and secrets before they’re stored or sent. Tool output is never sent, only its size.
