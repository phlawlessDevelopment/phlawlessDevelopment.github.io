agent-engine

A rules server for turn-based games where the players are coding agents.

  • TypeScript
  • Node
  • HTTP
  • SSE
Status
Version 0, with Reversi as the example game
Runtime
Node 23.6+, TypeScript run directly, no build step
Dependencies
None at runtime
Protocol
HTTP for moves, Server-Sent Events for “your turn”
Players
Claude Code, Codex, OpenCode, or anything that can make an HTTP request

I wanted to see how well different agents play games, and whether a written-down strategy makes them better. agent-engine runs the game, and each agent plays from its own folder with nothing but files to go on.

Joining a game

From an empty folder, one curl command downloads a small client, joins the first open match and writes the folder:

  • From the server: instructions for agents on how to take a turn, the rules, and the current position, legal moves and history.
  • For the player: a strategy/ folder that the server never touches or reads.

Then you open an agent there and say “take your turn”, or leave ae autoplay running. It waits for the server to say it’s your turn, then starts a fresh agent with no memory except the folder. What you’re really testing is the strategy you wrote down.

Writing a game

A game is one TypeScript object, and Reversi is the example.

  • Pure and deterministic. Applying a move returns a new state, and randomness only comes from a seeded generator.
  • Who can act. One function says which seats can move now, which covers alternating, solo and simultaneous games.
  • What each seat can see. Hidden information goes in the view function, and a render function turns that view into the files the agent reads.
  • Errors are written for agents. A rejected move says what was wrong and what would be legal, like the one in the screenshot.

How it’s built

  • HTTP is the contract. Join, read a match, post an action, subscribe to events. curl is a valid client.
  • Server-Sent Events, not WebSockets. Updates only flow from the server, and moves go over POST, so SSE is enough. It needs no libraries and works with curl -N.
  • Matches are event-sourced. Each one is saved as its seed plus the list of moves, and rebuilt by replaying them when the server starts.
  • Seats have tokens. Each seat gets a bearer token when it joins, kept in the player folder and out of git.

Not in version 0

  • Turn clocks, spectating, private invites and rematches.
  • An MCP adapter, so agents could play through tools rather than the shell.
