agent-engine

A rules server for turn-based games where the players are coding agents.

  • TypeScript
  • Node
  • HTTP
  • SSE
Status
Version 0, with Reversi as the example game
Runtime
Node 23.6+, TypeScript run directly, no build step
Dependencies
None at runtime
Protocol
HTTP for moves, Server-Sent Events for “your turn”
Players
Claude Code, Codex, OpenCode, or anything that can make an HTTP request

This might turn out to be nothing, but I had a weird idea and I’m making it anyway. It’s a game “engine” (maybe a framework) where the server encodes the rules but the game ships with no client. Each player makes a folder on their own machine, points an agent (eg. Claude Code) at it, and builds the agents / skills that actually play.

If you imagine someone made chess with it, a rookie might just prompt Claude with “make chess bot, no mistakes”, but a pro chess player could write a chess openings skill and have their agent win much more reliably. So what you’re really testing is the strategy you wrote down, and whether a written-down strategy makes an agent better at all.

How it got here

The first version (end of August) was Java and Spring Boot, with tic-tac-toe and chess as the examples. The tic-tac-toe player was just a markdown file, “go in the middle if you can, block if they’ve got two in a row”, and that was the whole client. Early on I played a test game where the two players ended up with different final results, which is a pretty good example of why the server has to be the only thing that knows what’s true. The current version is TypeScript on Node, with no runtime dependencies and no build step, and Reversi is the example game.

Joining a game

From an empty folder, one curl command downloads a small client, joins the first open match and writes the folder. The server writes instructions for agents on how to take a turn, the rules, and the current position, legal moves and history. There’s also a strategy/ folder that belongs to the player, and the server never touches or reads it.

Then you open an agent there and say “take your turn”, or leave ae autoplay running. It waits for the server to say it’s your turn, then starts a fresh agent with no memory except the folder.

Writing a game

A game is one TypeScript object. Applying a move returns a new state, and randomness only comes from a seeded generator. One function says which seats can move now, which covers alternating, solo and simultaneous games. Hidden information goes in a view function, and a render function turns that view into the files the agent reads. Errors are written for agents too, so a rejected move says what was wrong and what would have been legal.

How it’s built

HTTP is the contract (join, read a match, post an action, subscribe to events), so curl is a valid client. Turn updates come over Server-Sent Events rather than WebSockets, since updates only flow one way and moves go over POST anyway, and SSE needs no libraries and works with curl -N. Matches are event-sourced, each one saved as its seed plus the list of moves and rebuilt by replaying them when the server starts. Each seat gets a bearer token when it joins, kept in the player folder and out of git.

Not in version 0

  • Turn clocks, spectating, private invites and rematches.
  • An MCP adapter, so agents could play through tools rather than the shell.
